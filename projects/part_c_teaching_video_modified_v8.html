The lesson

Store rules as data, not code.

Too much logic in the code
filter( rule1 | rule2 | rule3 | ... | rule9 )
Works, but it is hard to read, hard to check, and annoying to update.
Cleaner idea
cases <- tribble(date, price) data |> inner_join(cases)
Put the rules in a small table, then join. Add one row to add one rule.
Why this matters: we still reference the code, but the main idea is simple. Treat the matching rules like data you can inspect, not like a long paragraph of logic.
Application

Apply the same idea to build ab_5 and ab_6.

Step 1 — build ab_5
ab_5 <- ab_4 |> inner_join(transition_lookup)
The lookup table keeps only the 4 allowed transitions and adds the price change label at the same time.
Step 2 — build ab_6
ab_6 <- ab_5 |> inner_join(tibble_planograms)
Instead of a long case_when(), we join the shelf reference table to add planogram.
ab_5: filter to the valid scenario types and attach the scenario label.
ab_6: attach shelf position in one clean step that is easier to reuse across devices.
The setup

Three kinds of price show up in the data.

If the same price move creates different sales reactions, then the elasticity will look different too.
The catch

A promotion bundles more than a price.

Promotion

Lower price. Big signs. Endcap. Flyer. Attention.

Test

A new number on the shelf. Nothing else.

So when sales jump, is it the price or the shouting?
Step 1 Define the row labels

What the four scenario labels mean.

Regular into regular

Normal price to normal price. Everyday repricing, not an experiment.

Regular into sale

A promotion starts. The price changes and the extra marketing turns on.

Sale into regular

A promotion ends. The price goes back to normal and the extra marketing turns off.

Test into test

Test price to test price. A planned experiment where only price changes.

Why regular and test are different
Regular into regular is routine repricing in normal business. Test into test is a planned experiment meant to isolate price.

What to focus on
Focus on the slope of the line. A steeper line means sales changed more when price changed. A flatter line means sales changed less.
How to compare
Read down one column at a time. The green test row is the cleaner price effect. The promo rows mix price with extra marketing.
Main takeaway: compare slopes inside the same shelf column. If the promo rows are steeper than the green test row, promotions are overstating true price sensitivity.
The punchline

The test line is flat. The promo line is steep.

Rows = price change type · Columns = shelf position · Focus on the Eye Level column first

Finding 1. Test line is flat

The randomized Test rows are nearly horizontal in every column. That is the true causal price elasticity. It is much smaller than the others.

Finding 2. Yellow sticker bias

Promo Start and Promo End slopes are steeper. Promotions bundle signs, endcaps, and digital ads. The sales jump is price plus marketing, not price alone.

Finding 3. Shelf position does not explain it

The gap between the Test row and the promo rows persists across all four shelf positions. Shelf placement is not the explanation. The bias is structural.

Takeaway

What to remember.

Trust the tests

They isolate price. Clean elasticity.

Discount the promos

Their slope includes marketing, not just price.

Shelf matters

Always compare inside the same shelf.

Business impact

Use test data to set regular prices. Not promo data.
